# 2026-08-17 22:15 JST | 引き継ぎメモリ（Handover Memory）の導入 — AIに「1枚だけの記憶」を持たせる

「R5のP01は、R1でP04に裏切られた記憶を持っているか？」という問いを起点に調査した結果、**持っていない**と
判明した（LLMコールは1-shot、チャット/戦略メモは毎ラウンド消去、過去の契約違反もvisible_stateに出ない）。
談合ゲームの核心である「裏切りを覚えて次に活かす」が構造的に成立していなかった。

**要求:** 最初に「全ラウンドの客観履歴を配布する」3段階プランを提示したところ、ユーザーから
「現ラウンド分の会話は生きてるんだよね。memoryだけでいい気がする。500-1000文字ぐらいの自由フィールド。
前ラウンドのmemory＋現ラウンドの会話歴＋現ラウンドの契約＋現ラウンドの結果等をもとに次ラウンド繰り越しの
自由メモリ、好きなように書きなさい。これのみ記憶として引き継がれます、という設計はどう？
モデルの性能も出るしね」という対案が出た。前案（履歴配布）より秘匿漏れリスクが低く、ゲーム性が出て、
コストも増えないと判断しこちらを採用。実装を承認され実行した。

**実行:** commitフェイズは決着前で「今ラウンドの結果」が存在しないため、Settlement/Finance完了後に
専用の`_phase_reflection()`を新設（`game.py`の`run()`に第6フェイズとして追加）。
`PlayerAgent.reflect()`は`choose_double_up()`と同様の非abstractデフォルト（no-op）とし、Bot 8種・
`StubAgent`を無改修に保った。`build_reflection_prompt()`で当ラウンドの会話全件・契約・市場結果・
資金状況を材料に`{"memory": "..."}`を要求し、`LLMAgent.reflect()`はリトライなしの1コールで
`self._memory`（常に最新1枚のみ、累積しない）を更新する。**API失敗・空応答時は前ラウンドのメモを
そのまま維持**（空文字での上書き禁止）。`extract_memory()`はJSON化に失敗しても応答テキストそのものを
採用し`ParseError`を投げない自由記述専用の経路とした。`negotiate()`/`commit()`のプロンプトに
`memory`を注入する一方、`choose_double_up()`（純粋なTAKE/DOUBLE判断）には注入しない。
`config.memory_enabled`（既定`False`、S2プリセットのみ`True`）で旧挙動を完全に保持。

前提調査の過程で、前ラウンド結果の参加者表示が`参加6人 → 勝者 P01`のように**人数へ潰されており**、
§8.1が公開情報と定義する「使用カード（決着後）」が一度もプロンプトに出力されていなかった実装漏れも
発見し、あわせて是正した（Part 0: `_last_round_results`に`commits: [{"player_id","card_rank"}]`を
追加し、`P01[ROYAL_FLUSH]★, P02[FLUSH]★, ...`の形式で描画。3段フォールバックで既存テスト・旧形式
dictとの後方互換を維持。霧ラウンドは`card_rank`を`"FOG"`に伏せる）。

**検証:** `uv run pytest tests/test_prompt_market_info.py -v`（既存9件＋新規6件=15件PASSED）、
`uv run pytest tests/test_memory.py -v`（新規35件PASSED）、`uv run pytest tests/ -q`
**423件PASSED**（既存382件＋新規41件、失敗ゼロ、回帰なし）。`uv run python scripts/dry_run.py`
（Bot12人版、memory_enabled既定Falseの経路）が例外なく完走。`uv run python scripts/simulate.py
--games 1000`（S1既定・memory_enabled=False）が3.2秒で完走し`_phase_reflection`が即returnする
ことをコードレベルで確認済み（RNG消費・状態変更ゼロのため既存Bot統計への影響は構造的にありえない）。
加えて`--ruleset S2 --games 100`（memory_enabled=True）も0.6秒で例外なく完走し、Reflectionフェイズの
実行パス自体を100試合分exerciseした。実プロンプトを目視し、「## 今ラウンド（R1）の結果」に
`P01[TWO_PAIR]★`形式の描画、「## あなたの記憶（前ラウンドから引き継いだメモ / これが唯一の記憶です）」
セクションが意図どおり出力されることを確認。LLM APIを使う試合はこの検証には使用していない。

**結論:** `config.memory_enabled`の既定値`False`により全既存プリセットの挙動は不変。S2プリセット
（`default_8_s2`/`baseline_v1_s2`）でのみ有効化され、1試合あたり約+95コール・約+$0.42（実測ベース試算、
`COST_LIMIT_TOTAL=12.0`に対し十分な余裕あり）。エンジンの賞金計算・契約判定ロジックは無変更。
DM本文が全プレイヤーに見えている別件のバグ（`game.py:949`、§8.2が秘匿と定義する内容が全員に描画される）
を調査中に発見したが、本件のスコープ外として着手していない（現状のmemoryは「自分が見聞きした全部」に
DM内容も含まれてしまうため、修正すればmemoryは初めて真に主観的な記憶になる。順序としては本件を先に
入れて問題ない）。
