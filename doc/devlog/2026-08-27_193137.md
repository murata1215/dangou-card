# 2026-08-27 19:31 JST ｜ サイクル6.1: thinking/temperature 分岐・grok timeout・隠れ思考予約値の修正

## 背景

Cycle 6（`doc/devlog/2026-08-27_074110.md`）のモデルレジストリ監査で、15モデル×1callスモーク中に
「アダプタのロジック変更が必要」として保留・報告のみで停止した3クラスの障害があった:

1. L1(claude-haiku-4-5) / M5・H5・K25_EVAL(Moonshot) が thinking 有効時に HTTP 400
   （Anthropic: "temperature may only be set to 1 when thinking is enabled or in adaptive…"、
   Moonshot: "invalid temperature: only 1 is allowed for this model"）
2. M4(grok-4.5) が 61.1s でタイムアウト（timeout_seconds既定60秒）
3. H4(grok-4.6) の実費が予約(hidden_thinking_reserve_tokens=1536)を19%超過
   （実測 reasoning_tokens=6756 に対し予約が不足）

本サイクルはこの申し送り4件（3件の障害＋回帰テスト不足）を閉じる。

## やったこと

### 修正1: thinking有効時のtemperature衝突（`llm/adapters.py`）

`THINKING_TEMPERATURE_LOCKED_PROVIDERS = ("Anthropic", "Moonshot")` という許可リストと
`_thinking_enabled_payload()` ヘルパを追加。Anthropic/OpenAI互換両アダプタの `complete()` に、
①思考が有効なpayloadが乗っている ②providerが許可リストに含まれる ③`supports_temperature=True`
の3条件がすべて真のときだけ `temperature=1.0` を強制する分岐を追加した（各アダプタ4〜5行）。

**本走ロスターL1〜L6への影響がゼロであることの構造的根拠**:
- `llm/llm_agent.py:227` の本走呼び出しは `request_options` を一切渡さない
- Moonshotの registry `extra_params` は既定で `{"thinking": {"type": "disabled"}}` のため
  `_thinking_enabled_payload()` は False を返す
- xAI/DeepSeek/Google/OpenAIは許可リスト外

これを `tests/test_thinking_temperature.py::TestCoreRosterRequestSnapshotUnchanged` で、
L1〜L6の送信リクエスト辞書をAPI 0件のフェイククライアントで丸ごとスナップショット固定した。

### 修正2: M4(grok-4.5) timeout 60→180秒（`llm/models.py`）

Cycle 6と同型の「60秒の壁」（H4の61.2s×2と同様の61.1sタイムアウト）に対し、
H4で実績のある180秒へ引き上げた。

### 修正3: H4/M4 の隠れ思考予約引き上げ（`llm/models.py` + `scripts/model_matrix.py`）

検証スモーク（下記）でH4 reasoning_tokens=7746（Cycle 6の6756よりさらに上振れ）、
M4 reasoning_tokens=2035（timeout修正で初めて実測取得）を確認した。
既存モデル群と同じ経験的安全率（実測×1.1〜1.5）を踏まえ、`ceil(実測×1.2)`を512単位へ
切り上げて反映した:

| Key | 変更前 | 変更後 | 根拠 |
|---|---:|---:|---|
| H4 | 1,536 | **9,728** | 実測7746(Cycle6.1) / 6756(Cycle6) の大きい方×1.2→9296を512単位切上げ |
| M4 | 1,024 | **2,560** | 実測2035×1.2→2442を512単位切上げ |

これに伴いPhase 2のCORE_18予約合計が $0.24067398 → $0.37276999 に増加し、
`PHASE_DEFAULTS[2]["max_cost"]` の旧上限$0.25を超過するため、$0.25→**$0.40**へ引き上げた
（headroom $0.02723001・6.8%。`max_cost_per_model`$0.035は据え置き。これはPhase 2実行時の
事前予約ガードの上限であり、実費が増えるわけではない。Phase 2は本サイクルで実行していない）。

## 結果

- **thinking有効時のtemperature=1.0強制でAnthropic/Moonshotの400は消えた**（M5/H5/M4は成功、
  L1は温度衝突は解消したが**別の未解決事象**あり: 下記「非変更・非実施」参照）
- **M4が180sで成功**、reasoning_tokens=2035を実測（旧予約1024の約2倍）
- **H4の隠れ思考予約 1,536 → 9,728**（Cycle6実測6756・Cycle6.1実測7746の大きい方×1.2）。
  これに伴い**Phase 2予約上限 $0.25 → $0.40**（実費ではなくガードの上限）
- **本走ロスターL1〜L6の送信内容は1byteも変わらない**ことをスナップショットテストで固定
  （`request_options`を渡さない本走経路は3重にガードされ新分岐に入らない）
- `uv run pytest tests/ -q` → **1401 passed**（Cycle 6終了時1382 + 新規19）
- `uv run python scripts/dry_run.py` → 12人版正常完了（生還0人、イベント578件、Cycle 6と同結果）
- スモーク累計実費 **$0.27528**（承認上限$0.60の46%）

## 結論・次

- 修正1〜4はすべて完了。単価数値は1つも変更していない。
- **L1(claude-haiku-4-5)は"adaptive thinking is not supported on this model"という新規400が判明**
  （温度衝突とは別の、モデル自体がadaptive thinkingモードを非対応という制約）。これは
  `scripts/replay_probe.py`のTHINKING_REQUEST_OPTIONS（編集不可ファイル）が送るペイロード自体の
  問題であり、本サイクルのスコープ外として保留・報告する。thinking系スクリプトでL1を使う場合は
  `--thinking off`のみ使用可能。
- H4の予約9,728も実測ベースの経験的マージンであり、provider保証の上限ではない。今後さらに
  上振れする可能性は残る。
