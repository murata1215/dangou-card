# 2026-08-30 19:55 JST ｜ サイクル9.2: v0.9 プロンプト文面（Free Cash 廃止の反映＋本戦分析5点）

## 背景

サイクル9.1でエンジン側の支払可能額ゲートを刷新し、`GameConfig.free_cash_mode` ∈ {`debt`,`cash`,`entry_fee`} と `engine/player.py::spendable_cash()` を新設した。`GameConfig.baseline_v1_s2` は既に `free_cash_mode="entry_fee"` に切り替わっており、エンジンは借入金を交渉資金として使える（今Rの Entry Fee 分だけ留保）。

しかし `llm/prompt_builder.py` は一切追随しておらず、system prompt は「Free Cash = max(0, 現金 − 借金残高)」「開始時は全員 Free Cash=0」と説明し、「あなたの状態」に `Free Cash: 0万円` を表示し、「いま選べないもの: transfer・bounty_post（Free Cash 0）」と**エンジンが許可する行動を禁止と告げていた**。モデルは v0.8 の経済を信じたまま v0.9 のエンジンで戦っていた。

あわせて v0.8 本戦分析（`doc/analysis/trial_v08_l12_r12_20260830_analysis.md` §10）の指摘5点（G1〜G5）にも対応した。

## 実施内容

`llm/prompt_builder.py` のみを変更（`engine/` は無変更）。`free_cash_mode == "debt"` では従来文言（Free Cash）を維持する分岐を残し、`entry_fee`/`cash` モードでのみ新文言に置換した。

### Step 1: system prompt

`RULES_SUMMARY` にプレースホルダを追加し、`build_system_prompt` で `config.free_cash_mode` を見て debt / non-debt の2種類の文字列を組み立てる方式にした。

- 「## Free Cash」節 → 「## お金の使い方」節（entry_fee/cashモードのみ）。支払可能額 = 現金 − 今RのEntry Fee という定義を明記
- 借入・利息・強制返済節を「借入額は交渉予算の上限でもある」旨に更新
- RULES_SUMMARY内の残り12箇所のFree Cash言及（型A契約・カードトレード・状態秘匿など）を「現金」「支払可能額」表記へ置換

### Step 2: `build_loan_prompt`

- 「借入金は交渉資金として最初から使える」旨の追加文（entry_fee/cashモードのみ）
- `mandatory_repay_enabled=True` のときのみ出す参考表「## 賞金を1度も取れなかった場合の目安」を新設。`_simulate_zero_prize_path()` を新規実装し、既存の `_compute_finance_forecast()` を再利用してエンジンの1ラウンド順序（Commit→Settlement→Finance）を正確になぞった。破産ラウンドには事由（`entry_fee`/`mandatory_repay`）を併記

### Step 3: negotiation / commit / double_up / reflection

- 「あなたの状態」の `Free Cash: X万円` 行を `支払可能額（現金 − 今RのEntry Fee）: X万円` に置換（reflection/double_upは行ごと削除、debtモードは従来行を維持）
- `_available_negotiation_actions` のgatingを `spendable_cash` 基準に変更
- トレード受諾プレビュー・署名待ちプレビューの型A表記を現金/支払可能額ベースに更新
- **G1**: `_render_type_a_shortfall_warning()` を新設。今R・次R期限の型A義務を合算し、賞金ゼロ想定での現金不足を執行前に警告する。次R期限分は Entry Fee×2 に加えて `_compute_finance_forecast` の強制返済見込みも差し引く（承認済み計算式）
- **G2**: `_render_card_trade_propose_template()` を新設。`card_trade_propose` が選択可能なときのみ、生存者・手札から機械的に埋めた雛形を提示
- **G3**: 提案者本人への `contract_sign` 非表示は調査の結果既に正しく実装済みと確認（`signed_by` に提案者が自動署名済み）。コード変更なし、回帰ガードのテストのみ追加
- **G4**: reflection末尾の出力指示直前に「このフェイズでは action や strategy を出力しないでください。出力は `{"memory": "…"}` だけです」を追加

### Step 4: テスト

既存テストのうちentry_feeモードに関わるものを新文言に更新（`tests/test_prompt_v08.py` 3箇所、`tests/test_cycle5_prompt_salience.py` 2箇所、`tests/test_prompt_action_paths.py` 1箇所）。debtモード用の `tests/test_llm.py` は旧文言のままガードとして維持し、その旨のコメントを追加。

新規 `tests/test_prompt_v09.py`（20件）を作成し、Free Cash文言の完全排除・debtモード後方互換・支払可能額行とgating・G1〜G4の発火/非発火/合算・system prompt文字数上限を検証。

system prompt長の変化（8,187→8,181字）に伴い、`tests/test_model_matrix.py` と `tests/test_phase2_schema.py` のH1予約額・M3/H3コスト見積もりのハードコード期待値も実測値へ更新（八度目の期待値更新、コメント付き）。

### Step 5: プロンプトダンプ v3

`scripts/dump_prompts.py` を更新し `doc/prompt_dump/actual_prompts_20260830_v3.md` を新規生成した。

- パターンBのダミーに、次R（R8）期限・現金不足の型A義務（G1実演）と、自分（P07）が提案者の署名待ち契約（G3回帰ガード実演）を追加

生成後、目視・grepで以下を確認した:
