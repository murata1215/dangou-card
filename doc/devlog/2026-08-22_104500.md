# Viewer修正: R12 P12 脱落イベント重複表示の解消

## 背景

完走済みrun `trial_C_l12_r12_20260822 / game01` のR12で、`viewer/log_parser.py` の
`get_round_states()` が返す `rounds["12"]["eliminated"]` にP12が2件重複して入る
既存挙動が確認された。`get_game_state()`（生存数・ゲーム結果）は既に重複排除されており
実害は無かったが、ラウンド脱落者一覧・round-detailで同一人物が2回表示されていた。
先行の `AUTO_COMMIT_FAILURE` 取りこぼし修正（`2026-08-22_094134.md`）とは別件で、
それ以前から存在するバグと確認済み。

## 原因

実ログを直接確認したところ、R12のP12には脱落系eventが2件出ていた:

- `SURVIVAL_CHECK`（`result="eliminated"`, `reason="condition_not_met"`）
- `FORCED_LIQUIDATION`（`reason="condition_not_met"`）

同一eventの二重処理ではなく、engineが仕様通り2種類のイベントを出す設計（R12生存条件未達の
確定後にforced_liquidationが清算処理として発火）。

`get_round_states()` 内の `rd["eliminated"]` へのappend地点は3箇所
（`AUTO_COMMIT_FAILURE` / `BANKRUPTCY`・`FORCED_LIQUIDATION` / `SURVIVAL_CHECK`）あり、
いずれも重複排除ガードが無かった。全ラウンドを調べたところ、`ELIMINATION` と
`MANDATORY_REPAY_FAILED` は `get_round_states()` でそもそも未ハンドル（`ELIMINATION_EVENT_TYPES`
定数は `get_game_state()` 側でしか使われていない）だったため、既存の二重発火
（R3=P11, R5=P02, R9=P06, R11=P01の各ケース）は偶然1件に収まっていた。
**`SURVIVAL_CHECK` と `FORCED_LIQUIDATION` の組み合わせだけが「両方ハンドルされる」唯一のケース**
であり、これがP12のみ重複表示となった理由。

`get_game_state()` は該当箇所に `if pid not in eliminated` の先勝ちガードがあるが、
`get_round_states()` には同等のガードが無かった、という構造非対称が根本原因。

## 修正内容

`viewer/log_parser.py`:

- `get_round_states()` 内にローカルヘルパ `add_elimination(rd, player_id, reason)` を追加。
  同一round・同一playerが既に `rd["eliminated"]` に存在する場合は追加しない（先勝ち、
  `get_game_state()` の既存セマンティクスと統一）。
- 3箇所の `rd["eliminated"].append({...})` を `add_elimination(rd, ...)` 呼び出しに置換。
- `get_game_state()` 側・契約 `outcomes`（god限定の生履行イベント一覧）・
  `get_player_timeline()`（LLM callログベース）は無変更。複数の脱落系eventが実際に
  発生した場合でも、生のtimeline/outcomesは間引かれない。

## テスト

`tests/test_viewer.py` に `TestEliminationDeduplication` を8件追加:

1. `test_survival_check_and_forced_liquidation_dedup` — 合成ログでR12にSURVIVAL_CHECK+FORCED_LIQUIDATIONを出し1件に正規化
2. `test_real_trial_p12_r12_single_entry` — 実trialでP12 R12が1件（run不在ならskip）
3. `test_real_trial_p09_r6_still_single` — 同runでP09 R6が引き続き1件（巻き戻し防止）
4. `test_elimination_plus_forced_liquidation_dedup` — ELIMINATION+FORCED_LIQUIDATION（P02/P11型）で1件
5. `test_bankruptcy_single_event_unchanged` — BANKRUPTCY単発はそのまま1件
6. `test_dedup_view_parity` — public/godで一致
7. `test_dedup_does_not_change_survivors` — get_game_state()側のsurvivors/eliminatedは不変
8. `test_raw_outcomes_keep_multiple_events` — 契約outcomes（god限定・生データ）は間引かれない

既存 `TestAutoCommitFailureElimination` 6件も含め、対象テスト計50件PASS。

## 影響範囲

Engine・trialログ・God/Public秘匿境界・`get_game_state()` は無変更。LLM API送信なし。
本修正は `viewer/log_parser.py` の `get_round_states()` のみに閉じる。

**Viewerは未再起動**（現行稼働PIDのまま、旧コードが実行中）。再起動は別途人間承認後に実施する。
