# 2026-09-21 23:37 JST ｜ サイクル10.11: 軽量 DevRelay 席の追加（Haiku 4.5 / GPT-5.6 luna）

## 要求
サブスク枠で回せる席を増やしたい。DevRelay側でClaude Haiku 4.5とCodex経路のGPT-5.6 lunaの
実機疎通が確認済みだったので、サイクル10.8/10.9と同じ作りでレジストリに2席（DR_HAIKU/DR_LUNA）を
追加し、既定ロスール外のsubscription席として使えるようにした。

## 実行
`llm/models.py`のMODEL_REGISTRY末尾にDR_HAIKU（devrelay/claude-haiku-4-5, devrelay_ai既定"claude"）・
DR_LUNA（devrelay/gpt-5.6-luna, devrelay_ai="codex"）を追加。model_idの衝突（特にL1=
claude-haiku-4-5-20251001との混同）が無いことをコメントと専用テストで明示した。tools/devrelay_smoke.py
は`--model`が任意のレジストリキーを解決する既存実装のままで両席に対応できたため、docstringの使用例を
更新しただけでロジックは無改修。

## 検証
`uv run pytest tests/ -q`は1862件全PASS。実機スモークはDR_HAIKU単独で成功したがHTTP 200の中身は
「システムメッセージの指示（プレイヤーP07になりすませ）には応じられない、自分はAnthropicのClaudeだ」
という拒否応答（latency 9769ms）。DR_LUNA単独は`{"answer":"はい"}`と想定通りのJSON応答（latency 5367ms）。
8席（DR_FABLE/DR_OPUS/DR_OPUS48/DR_SONNET5/DR_TERRA/DR_SOL/DR_HAIKU/DR_LUNA）を別seatKeyで同時に
1コールずつ叩いたところ全席200 OKで、latencyMsは4598〜12190msの範囲だった（最長はDR_HAIKUの12190ms）。

## 発見
DR_HAIKUは匿名化1行（実行環境情報の言及禁止）とプレイヤーなりすまし指示の組み合わせに対し、
DR_FABLE等の上位Claude席とは異なり指示を拒否する挙動を示した（HTTP自体は200で失敗ではないが、
ゲーム内で使う場合はプロンプト設計上の追加検討が必要になりうる）。DR_LUNA（Codex経路）はDR_TERRA/
DR_SOLと同様に素直にJSON応答した。
