# 2026-09-21 08:06 JST ｜ サイクル10.9: DevRelay 経由の Codex 席（terra / sol）の追加

DevRelayのraw-completionが `ai: "codex"` に対応したという知らせを受け、ゲーム側にCodex実験席を2つ足す作業だった。これまでのDevRelay席（Fable/Opus/Opus 4.8/Sonnet 5）はすべてClaudeで、`ai`フィールド自体を送っていなかった。DevRelay側の既定AI設定に依存する状態だったので、まず「どのAIを使うつもりか」を毎回明示送信するように変え、その上でCodexの新しい2モデル（gpt-5.6-terra / gpt-5.6-sol）を既定ロスター外の実験席として追加した。

実装では`ai`を送るだけでなく、Codex固有の癖にも手当てした。Codexの既定挙動は「他のエージェントに作業を振れる」前提らしく、談合カードでは1プレイヤーとして単独で振る舞ってほしいので、Codex席にだけ「委譲手段は無い」という1行をsystemプロンプト末尾に足した。逆にレスポンス側の`ai`が要求と食い違ったら気づけるようにWARNINGログを仕込んだが、古いDevRelayサーバーが`ai`キー自体を返さないケースまでWARNING扱いにすると誤検知になるので、キー欠落は素通りさせるという線引きにした。

実機で叩いてみると、DR_TERRAは`ai(sent)=codex`に対して`ai(resp)=codex`が返り、応答テキストも`{"answer":"はい"}`と談合カード想定のJSON形式で返ってきた。DR_SOLも同様。5席（Claude 3席・Codex 2席）を別seatKeyで同時に1コールずつ叩いても全部200で、レイテンシは4.9秒〜7.5秒のばらつきに収まった。並走で詰まったり片方だけ失敗する様子は見られなかった。

テストは新規6件（ai送信のclaude既定・codex送信＋追加行・ai記録・食い違いWARNING・欠落時WARNINGなし・不正ai値の構築時拒否）と結合1件（fakeサーバーのaiエコー）を足し、既存のレジストリ不変条件テスト（フィールド数のスナップショット）も更新が必要だった——`ModelInfo`にフィールドを足すと必ずこのテストが落ちる設計になっていて、今回もその通りに検知された。全1849件PASS。

発見としては、レジストリのフィールド追加を検知する固定リストのテスト（`test_model_info_fields_include_phase2_and_temperature_overrides`）が想定通り機能し、うっかり更新を忘れるミスを防いでくれた。もう一つ、Codex席のスモーク応答は0.7秒〜9秒の間で揺れており、Claude席より若干バラつきが大きい印象があったが、サンプル数が少ないため一般化はできない。
