# 2026-09-19 16:37 JST ｜ サイクル10.3: 目的文の強化と順位通知

## 要求

10.2（首位公示）は首位IDのみの公示で下位プレイヤーは自分の位置を知れず、「生存できればいい」という
守りに流れる誘因が残っていた。本サイクルでは (A) v0.7 §1.3 の目的文（「生存は最低条件、総合1位が最高評価」）
を system prompt 先頭の新設 `## 目的` 節へ昇格し毎ラウンド全4フェーズで再掲する、(B) 各プレイヤー本人にのみ
自分の資産順位（`4位/6人`、同率は`同率2位/6人`）を通知する（順位起因の有利・不利処理は一切なし）、の2点を実装。

ユーザーからの2件の修正指示（実行前diff承認時）: ①system prompt長は9,086字案（マージン14字）を却下し、
既存文言を追加圧縮して**9,000字以下・上限9,100字との差100字以上**を確保。type_c OFF側8,300字上限も同様。
②順位＋目標リマインドは交渉プロンプトだけでなく commit / double_up / reflection の**全4フェーズ**に配置
（順位はMarket Open時点の値を1回計算し全フェーズで再利用）。

- `llm/prompt_builder.py`: `OBJECTIVE_LINES`（3行、フラグ非依存で常時）を`RULES_SUMMARY`先頭の新設

## 発見

- 「資産」という用語は現金と同義ではないが（未解決倍掛け預託・借金残高を含む）、R12生還者は両者が
  一致するため新3行「最終資産で1位」と既存文「最終現金が高いほど上位」の間に矛盾は生じない（意図的に
  仕様書の逐語を維持、用語統一は別サイクル案件）。
- `GAME_START`イベントのconfigダンプは固定サブセットのため、新設した`rank_notice_enabled`はログから
  ON/OFF判別できない（10.2の`leader_announce_enabled`と同じ既知の制約、対応は別サイクル）。
