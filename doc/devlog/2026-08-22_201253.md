実行: `viewer/static/index.html`のGod UI（`#god-toggle`/`#god-token-input`/`#god-status`）を
`#modal-overlay`内から`.header`末尾へ移設し、`#god-banner`はヘッダー直下・`#player-grid`の前に
常時可視の全幅バーとして配置した（要素idはすべて既存のまま流用し、既存テスト・CSSセレクタとの
互換を維持）。ボタン文言のみ`VIEW: PUBLIC 🔒`/`VIEW: GOD 🔓`に変更、`🔒 神視点 ON`/`🌐 公開`等の
既存必須文字列は維持した。JS側は`GOD_TOKEN_KEY`定数と`loadStoredGodToken()`/`storeGodToken()`/
`clearGodToken()`の3関数を新設し、God tokenをタブ限定の`sessionStorage`にのみ保存する
（`localStorage`はテーマ保存専用のまま不変）。`viewerFetch()`に403の一元downgrade処理
（`forceGodLogout()`: `godMode=false`化・`sessionStorage`削除・関連キャッシュ無効化・通知表示）を
追加し、`loadRoundDetail()`内にあった個別403分岐を削除して一元化した。God tokenトグルの
クリックハンドラを「ログイン（入力→実際のGod API呼び出しの200/403で判定、専用の確認APIは
新設せず`loadRoundDetail()`または`loadSituation()`の応答を流用）」「明示ログアウト
（`forceGodLogout()`→依存ビュー再取得）」に整理し、入力欄の`value`は読み取り直後に必ず空へ戻す
（DOMへtoken文字列を残さない）。`closePlayerDetail()`と試合セレクタ変更ハンドラからGod状態の
破棄を削除し（ラウンド依存キャッシュのみリセット）、モーダル再オープン・試合切替を跨いで
God認証が維持されるようにした。初期化処理に、`loadGames()`より前でsessionStorageからtokenを
読み出し楽観的に`godMode=true`から再開する復元ロジックを追加した（無効な場合は起動時に必ず
呼ばれる`loadSituation()`が403を検知し、`viewerFetch()`内の一元downgradeで自動的にpublicへ
戻る設計。追加の検証APIは新設していない）。`style.css`には`.header .god-controls { margin: 0 0 0
auto; }`（右寄せ）と`body > .god-banner`（全幅バー用の余白リセット）のみ追加し、既存の
`.god-controls`/`.god-toggle`/`.god-banner`本体の定義は変更していない。`tests/test_viewer.py`に
`TestGodViewSessionAuth`（T1〜T10相当、10ケース: God UIがmodal-overlay外に存在すること、
VIEW: PUBLIC/GOD文言の存在、既存必須文字列の二重担保、sessionStorage使用でlocalStorage
不使用（テーマ以外）、tokenをURL/query stringに載せないこと、403の一元downgradeが
`viewerFetch()`内に存在すること、`closePlayerDetail()`がGod状態を破棄しないこと、明示ログアウトが
`sessionStorage`を削除すること、リロード復元が専用確認APIを新設せず既存`/rounds`検証を
流用していること、`style.css`の可視性セレクタ維持）を新設した。Plan §9に従い、
`rules/project.md`（God tokenの保存先を「localStorage等の永続領域・URL・git・ログ・devlogへ
残さない、sessionStorageは同一タブ内の再入力回避目的で一時保持を許可する」に更新）、
`doc/viewer_operations.md`（神視点節の操作手順を「ヘッダーのVIEW切替で1回解除・以後使い回し・
sessionStorage限定・タブ終了で失効」に更新）、`README.md`（同様のUI記述更新）の3文書を
同一サイクルで改訂した。`viewer/server.py`/`viewer/log_parser.py`は無変更（Python側の
