## 修正2: pass のログ・トレーサビリティ（優先度中）

`llm/llm_agent.py` の `negotiate()` にAPIを呼ばずPassActionを返す経路が複数あり、
`llm_calls.jsonl` に対応レコードが残らない11件（pass 439件中）の原因を特定・記録できるようにした。

- `engine/models.py` の `PassAction` に
  `source: Literal["llm","auto_no_news","cost_exceeded","budget_blocked","parse_failed","bot"] = "llm"`
  を追加（デフォルト値付きのため既存呼び出しは全て後方互換）
- `engine/game.py` の `NEGOTIATION_ACTION`（pass）ログに `"source": getattr(action, "source", "llm")`
  を追加
- `llm/llm_agent.py` の5箇所のpass返却点に該当sourceを設定
  （`cost_exceeded` / `auto_no_news` / `budget_blocked` / `parse_failed`×2）
- 案として検討した `llm_logger.log_auto_pass()`（非APIレコードをjsonlに追加）は、
  `scripts/llm_trial.py` がjsonl行数を総コール数・response_text有無をJSON率として集計しており
  コール数の水増し・JSON率低下というレポート回帰を招くため不採用
