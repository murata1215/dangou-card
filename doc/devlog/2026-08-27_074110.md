## 背景

5.5で上位モデル4種のうち2種（gpt-5.6-terra・grok-4.6）が「実行環境の不備」で除外された。18体ロスター（6社×上位/中位/下位）へ進む前に、`llm/models.py`のレジストリ22エントリを「実在する・正しい単価・思考設定込みでJSONを返せる・タイムアウトが足りる」状態に監査した。ゲームルール・`engine/`には触れない、修正はレジストリ設定値のみ。

## やったこと

- Plan段階（API 0件）で監査項目1〜8を確定: レジストリ全21エントリのdump、単価の3列突合（registry／二次資料`doc/llm_api_pricing.md`／実走実測）、非推奨IDのgrep、パラメータ互換性、タイムアウト、思考設定と最小`max_output_tokens`、18スロット充足表、スモーク計画。
- 承認後、けいすけさん提供の2026-08-16版価格表を`doc/llm_api_pricing.md`として新規作成（**二次資料のため単価変更の根拠にはしない**）。`llm/models.py`にA〜D・Gの修正を適用: H4 `grok-4.6`のtimeout_seconds 60→180（5.5実測61.2秒×2の裏付け）、TERRA `gpt-5.6-terra`のmax_tokens_param→`max_completion_tokens`・supports_temperature→False（5.5のHTTP 400裏付け）、8エントリへ二次資料との差異コメント併記、`kimi-k2.5`実在確認用の評価専用エントリ`K25_EVAL`を新規登録。`tests/test_registry_18.py`の許可リストへTERRA追加、回帰テスト3件追加。

## 結果

- 修正Aの検証: **H4 `grok-4.6`が123.5秒で成功**（旧60秒なら確実にタイムアウト）。ただし`hidden_thinking_reserve_tokens=1536`に対し実測reasoning_tokensは6756（4.4倍）で、費用見積が実費より19%過小だった（新発見、数値変更はCycle 6のスコープ外として未実施）。
- 修正B/Cの検証: **TERRA `gpt-5.6-terra`のHTTP 400が解消**、5.9秒でJSON有効な応答。
- 承認済み事項(B)の検証: **`kimi-k2.5`の実在を確認**（400はtemperatureパラメータ起因でmodel_not_foundではない）。L5は本サイクルでは変更しない。
- スモークで新規に3種の障害クラスを発見: (1) Anthropic/Moonshot系がthinking有効時に`temperature`制約で400（L1・M5/L5/H5/K25_EVAL）、(2) `gpt-4.1`系がreasoning_effort非対応で400（M2/L2、世代遅れの裏付け）、(3) `grok-4.5`(M4)も60秒タイムアウト。いずれもアダプタロジック変更が必要なため未修正・報告のみ。
- 単価数値は1つも変更していない。H4の登録単価($5/$15)は二次資料($2/$6)と2.5倍食い違うが、予算ガードを高い方に倒す方針で据え置いた。DeepSeekの現行IDは`deepseek-v4-flash`/`deepseek-v4-pro`の2つのみと文書で確定し、18枠に1枠足りないことが確定した（選択肢はPlanに列挙、決定は保留）。
- 累計スモーク実費$0.3007（上限$1.00の約30%）。`uv run pytest tests/ -q`は1382 passed、`uv run python scripts/dry_run.py`も正常終了。
