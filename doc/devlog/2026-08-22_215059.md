# 2026-08-22 21:50 JST ｜ サイクル: Viewer プレイヤー詳細「神視点の秘匿情報」の player-scope 化

要求: ユーザー報告（「P06の詳細でP04→P05等、P11の詳細でP02→P05等、いずれも当該プレイヤーが
送受信者でないDMが多数表示される」）を受け、承認済みPlan（`/home/uso8m/.claude/plans/
linked-stirring-catmull.md`）に従いプレイヤー詳細モーダルの「🔒 神視点の秘匿情報」セクションを
player-scope化した。原因調査フェーズ（本サイクル直前）で、`viewer/log_parser.py`の
`get_player_round_detail()`末尾（`secret_events`ブロック）だけが同関数内の他フィールド
（`calls`/`result`）と異なり`pid`フィルタを一切持たず、`round_states["rounds"][round_num]`から
そのラウンドの**秘密DM全件・terms付き契約全件**をそのまま返していたことを実データ
（`logs/llm/trial_C_l12_r12_20260822`, 12人R12版）で確認済みだった。同一データでP06(R9脱落)・
P11(R3脱落)の`secret_events["messages"]`を計測し、それぞれ44件・51件中、本人関与はP06=7件・
P11=9件のみで、全12名平均で DM 78%・契約 81% が無関係という規模を実測した上でPlanを作成、
承認を得て本サイクルを開始した。

実行: `viewer/log_parser.py`の`get_player_round_detail()`（L792-797相当）を、round全体の
秘密メッセージ/契約を`round_messages`/`round_contracts`として保持しつつ、`_dm_involves_player()`
（`sender == pid` または `to == pid`、`to`が`list`型の場合は`pid in recipient`で判定し旧ログの
型ぶれに対応）と`_contract_involves_player()`（`proposer == pid or pid in parties`）の2ヘルパーで
絞り込んだ`player_messages`/`player_contracts`を返すよう変更した。返り値に`"scope": "player"`
（意図の明示用）と`"round_totals"`（`messages`/`contracts`の全体件数と`*_hidden`の隠れた件数のみ、
本文は一切含めない）を追加した。`round_totals`は`secret_events`オブジェクトの内側に置くことで
`view == "god"`の1分岐構造を保ったまま、publicレスポンスへの新規キー流出をゼロに保っている。
`viewer/server.py`（`check_view()`のsecrets.compare_digest検証・403条件）は無変更。既存の
`_safe_round_result()`（L638、契約を`parties`のみで絞る）は公開表示に影響するため意図的に
未変更のまま据え置き、`secret_events.contracts`（proposerも許容）との1件差はコード内コメントで
明記した。付随して、`viewer/static/index.html`の`renderRoundDetail()`内で発見した第2のバグ
（`const fr = detail.final_reflection;`が実際には存在しないtop-levelキーを参照しており、
正しくは`detail.result.final_reflection`のため、FINAL_REFLECTIONセクションが一度も描画されて
いなかった）も同サイクルで`const fr = result.final_reflection;`（既存ローカル`result`を再利用）
に修正した。同ファイルの秘匿DM描画（`secretMessages`）から、`anonymous_broadcast`が
`get_round_states()`で常に`visibility: "public"`のため`secret_events`へ絶対に入らず到達不能
だった匿名発言の描画分岐を削除し、DM専用に縮約した。セクション見出しを「🔒 神視点の秘匿情報
（この選手の関与分）」に変更し、`round_totals`から「このRの秘匿DM{n}件中、この選手が関与する
{m}件を表示（残り{hidden}件は状況パネル）」の件数ノートを追加、`round_totals`が`undefined`の
場合（静的ファイルのみ先にブラウザ反映された過渡状態）はノート自体を出さないガードを入れた。
空表示文言も「このRにこの選手が関与した秘匿イベントはありません」に変更した。UX比較として、
round全体を別セクションへ分離する代替案（Plan §3の案B）は、既存の状況パネル
（`index.html` L1113-1157、round全体のDM・契約・匿名実発信者を god で既に表示済み）が
同じニーズを既に満たしていると判断し、実装を見送った（重複防止）。

`tests/test_viewer.py`の`TestPlayerRoundDetail`に、既存`_make_trial`がP01単独fixtureで
本バグを構造的に検出できない弱点を補うため、P01/P02/P03の3人・無関係DM(P02→P03)と
無関係契約(C02: P02/P03)を含む`_make_multi_player_trial()`を新設し、8件の回帰テストを追加した:
無関係DM除外・受信DM保持・送信DM保持（過剰フィルタでsender一致のみに絞ると受信DMを
落としてしまう回帰を防ぐ番人）・契約のparties/proposer両対応かつP01/P03視点の対称性確認・
`round_totals`の不変条件（`len(messages)+hidden==totals`）・`to`が欠落/list型の境界ケース・
publicビューに`secret_events`キー自体が増えないことの固定、および静的HTML側で
`"const fr = result.final_reflection;"`存在・`"const fr = detail.final_reflection;"`
不在（バグ再発防止の否定側アサーション）を検証する1件。

検証: `uv run pytest tests/test_viewer.py -v` → **82 passed**（既存74 + 新規8）。新規テストの
