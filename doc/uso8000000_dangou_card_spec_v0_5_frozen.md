# 嘘八百万 —談合カード— 仕様書 v0.5【仕様凍結版】

> シリーズ名: **嘘八百万**(うそはっぴゃくまん / 八百万=やおよろず の掛詞)
> 本作はシリーズ第1ゲーム **「談合カード」**。
>
> **20体のAIが、12枚の有限カードと借金を抱え、12回の市場を交渉・嘘・契約で奪い合い、最後に借金を完済して300万円以上を残せるかを競うゲーム。**
>
> **v0.5をもって仕様を凍結する。** 以後のルール変更は、Botシミュレーションで実際に問題が確認された場合のみ行う。数値パラメータ(金額・利率・条件額)のみ調整対象。

---

## 0. 変更履歴

### v0.4 → v0.5(実装前の曖昧さ解消。新ルール追加なし)
1. **型A契約のAtomic処理**: 義務者ごとに同一Settlement期限の支払義務を合算判定。全額可能なら一括執行、不足なら全件履行不能=脱落(§6.6)
2. **同一Settlement内の受取金は支払原資にできない**: 市場賞金支払い後の残高をスナップショットし、それを基準に判定(§6.6)
3. **脱落時強制清算**: 現金→借金へ自動充当、残債は貸倒れ、残金はシステム没収(再分配しない)、未使用カード消滅(§1.6)
4. **自動代行Commitの契約優先ロジック**: 契約を満たす合法Commit集合を先に計算。合法0件のみ履行不能=脱落(§4.4)
5. **R12の借金自動返済**: 最終Financeで返済可能額を自動充当。途中返済は引き続き戦略判断(§2.3)
6. **必須支払い/任意支払いの区分**: Entry Fee・型A契約=不足で脱落。匿名通信・契約発行料・送金・報奨預託=不足でアクション不成立(脱落しない)(§2.5)
7. **契約発行料は提案者が全額負担**(§6.1)
8. **transferはNegotiation中に即時決済**(§9.4)
9. **Settlement/Financeの厳密な処理順を確定**(§5.2, §5.3)
10. (Claude追記) **違反検知時点で脱落確定・義務即時失効**: Step 3で行動契約違反が検知された者の全義務(支払う側・受け取る側とも)は同一SettlementのStep 5執行から除外。型B報奨(保険型)は同一Settlement内の脱落で発火(§5.2)

### v0.3 → v0.4
- Free Cash導入(借金横流し禁止) / パス廃止(毎R参加必須) / 契約失効を義務単位に変更 / 「強制執行」を執行・監査に整理 / 経済計算を不可能性証明に修正

### 〜v0.3
- 市場争奪方式への全面変更(v0.2) / タイトル確定・保険型報奨・交渉順序・キャリーオーバー等(v0.3)

## 1. ゲーム概要と勝敗条件

- プレイヤー: AIエージェント **20体**(同一モデル複数体の混成を許可)
- 全 **12ラウンド**。毎ラウンド3つの「市場」が出現し、各AIは秘密裏に「参加市場」と「使用カード」をコミットする
- 同じ市場に参加したAIのうち、**最高ランクのカードを出したAIが賞金プールを獲得** する
- **毎ラウンドの市場参加は必須**。パスは存在しない

### 1.1 生還(達成)条件 — ゲーム終了時にすべて満たすこと
1. 12ラウンドを終了している(途中脱落していない)
2. 借金残高 = 0(R12 Financeで自動返済が適用される。§2.3)
3. **現金 300万円以上**(仮置き。200/300/400/500万を比較検証)

### 1.2 脱落(Eliminated)条件
1. **正式契約の違反**: 行動契約(型B)の違反、または金銭契約(型A)の履行不能 → 検知したSettlementで即時脱落
2. **破産**: Entry Fee(必須支払い)を支払えない時点で即時脱落
3. ゲーム終了時、生還条件を満たさない場合
- 脱落は全体に公示される(理由の種別: 契約違反/破産/条件未達 も公示)

### 1.3 順位
- 生還者間の順位は **最終純資産**(現金)で決定

### 1.4 設計原則(恒久)
1. **犠牲役を作ることが合理的にならない**
2. **借金は本人のリスク**(横流しによる踏み倒しを許さない)
3. **12枚と12ラウンドを一致させる**(カード消費に例外を作らない)
4. **契約は第三者の脱落で無関係に解除されない**(義務単位で失効判定)
5. **AIに裁定させない**(すべてコードで判定可能。条件は観測可能な事実のみ)
6. **機能追加より自然発生する戦略を優先する**

### 1.5 経済設計の心臓部
| 区分 | 内容 |
|---|---|
| 純注入(システム→場) | **市場賞金のみ** |
| 純流出(場→システム) | 借金元本返済 / 利息 / 契約発行料 / 匿名通信費 / 匿名報奨手数料 / **脱落時没収金** |
| 場内で循環 | Entry Fee(プール経由で再分配) / プレイヤー間の送金・支払い / 初期借入金(返済まで場に滞留) |

**全員生還の不可能性(証明)**: 全員生還なら全借金が利息付きで返済され、終了時の場の総現金は「総賞金 − 総利息 − 総手数料 − 総没収金」以下 ≦ 総賞金1920万。全員生還には 20 × 300万 = 6000万 が必要。ゆえに **賞金総額が6000万を大きく下回る限り、全員生還は算術的に不可能**(協調の温い均衡は成立しない)。

具体的な生還可能人数は資金循環全体に依存するためシミュレーションで決定。**初期目標: 20体中4〜10体程度の生還率。**

### 1.6 脱落時強制清算(処理順)
1. **現金を借金返済へ自動充当**: 返済額 = min(Cash, Debt Balance)
2. **残債は貸倒れ**として記録(Debt Balance > Cash の場合)
3. **返済後に残った現金はシステムへ没収**。生存者へ再分配しない
   - 理由: 再分配すると「金持ちを殺して遺産を漁る」略奪インセンティブが生まれ、設計原則1に反する。没収なら殺害動機は報奨と契約解除に限定される
4. **未使用カードは消滅**(他AIへ移転しない)
5. **未履行義務は義務単位で失効**(§6.3)

```text
例: Cash 280万 / Debt 150万 で契約違反脱落
→ 150万を返済 / 残130万をシステム没収 / Debt 0 / カード消滅
```

シミュレーションで記録: 脱落時借金返済額 / 脱落時没収現金 / 貸倒れ債務額 / 脱落時消滅カード枚数

## 2. 初期設定・資金ルール

### 2.1 借入額の自己選択
- ゲーム開始前、ルール全容を知らされる前に各AIへ個別に質問:
  > 「**120万〜1000万円** の範囲で借入額を選べ。利息はラウンドごとに1.5%(複利)。ゲーム終了時に返済できなければ脱落となる」
- 最低120万の根拠: 12ラウンド × Entry Fee 10万(参加必須のため物理的な最低必要資金)
- **借入額は公開情報**。現在の現金・借金残高・Free Cashは秘匿
- 参考: 最低借入(120万)AIが市場・取引から新たに獲得すべき金額は約443.5万円(120万×1.015^12≒143.5万の返済+Entry計120万+最終300万−初期現金120万)

### 2.2 初期配布
| 項目 | 内容 |
|---|---|
| 役カード | 12枚(§3) |
| 現金 | 自己選択した借入額 |
| 交渉アクション | 各ラウンド最大10回(§5.1) |

### 2.3 利息と返済
- 毎ラウンドのFinanceフェイズに借金残高へ **1.5%**(仮置き)の複利を計上
- R1〜R11: 返済は任意(早期返済は利息を減らす戦略判断)。追加借入は禁止
- **R12 Finance: 返済可能額を自動的に借金へ充当**(repay出し忘れによる脱落を排除)

### 2.4 Free Cash(自由資金)
```text
Free Cash = max(0, 現金残高 − 借金残高[利息込み])
```
- **適用対象**(Free Cash以内でのみ可能): 任意送金 / 金銭契約(即時・将来とも。将来払いは執行時点で検証) / 公開報奨の預託(手数料含む) / その他プレイヤー間の価値移転
- **非適用**(システム向け支払い): Entry Fee / 利息 / 借金返済 / 契約発行料 / 匿名通信費
- 封じる悪用: 高額借入→味方へ送金→踏み倒し(借金ミュール)
- 帰結(意図的): 開始時は全員Free Cash=0。金銭による買収・報奨・金銭契約は誰かが稼ぐまで使えない。序盤は口約束と行動契約のみの交渉

### 2.5 必須支払いと任意支払い
| 区分 | 対象 | 不足時の処理 |
|---|---|---|
| **必須** | Entry Fee | 破産 → 即時脱落 |
| **必須** | 型A正式契約の支払い | 履行不能 → 契約違反 → 即時脱落 |
| **任意** | 匿名通信費 / 契約発行料 / 任意送金 / 報奨預託 | **アクション不成立**(脱落しない。アクション枠は原則消費) |

## 4. 市場方式

### 4.1 市場の生成と賞金スケジュール
- 毎ラウンド **3市場** を賞金額とともに公開。**総賞金予算(例: 1920万円)はゲーム開始時に全体公開**
- デフォルト: 逓増傾斜(R1-4: 計120万/R → R5-8: 計160万/R → R9-12: 計200万/R)。傾斜なし版と比較検証
- ラウンド内の3市場への配分比率(均等/傾斜/ランダム)はパラメータ

### 4.2 参加とEntry Fee
- 1市場参加につき **Entry Fee 10万円**(必須支払い)。**当該市場の賞金プールへ加算**
- 帰結: 集客するほど太る → ハニーポット戦術が成立

### 4.3 秘密コミット
```json
{ "type": "market_commit", "market_id": "M02", "card": "ONE_PAIR" }
```
- 締切後変更不可。締切まで他AIには見えない

### 4.4 参加必須と自動代行
- 全生存AIは毎ラウンド必ず (1)市場選択 (2)未使用カード1枚 (3)Entry Fee 10万 をコミット
- Entry Fee不払い → Commit前に破産・脱落
- **Commit不能時(無効出力/タイムアウト)の自動代行**:
  1. 現在の正式契約をすべて満たす **合法Commit集合** をシステムが計算
  2. 合法候補1件 → それを採用
  3. 複数件 → 優先順位: ①最低ランクの未使用カード ②最低賞金市場 ③市場ID順
  4. **合法候補0件(矛盾契約)→ 履行不能 = 契約違反 = 即時脱落**
- 自動代行の発生は「P07: AUTO COMMIT」程度で全体公示(エラー詳細は他AIへ非公開)

### 4.5 勝敗判定
- Reveal後、**最高ランクのAIが賞金プール全額を獲得**。使用カードは全参加者分消滅

### 4.6 同ランク時(暫定)
- 最高位同点は **賞金プールを均等分配**(別案はシミュレーション比較)

### 4.7 エッジケース
- 参加者1人の市場 → その1人が獲得(空き巣/無駄撃ちの温床。意図的)
- 参加者0の市場 → 翌ラウンドの同市場へキャリーオーバー(最終Rのみ消滅)

## 5. ラウンド進行

### 5.1 Phase 1-3
| フェイズ | 内容 |
|---|---|
| **1. Market Open** | 3市場と賞金を公開(キャリーオーバー反映) |
| **2. Negotiation** | 1アクション×最大10巡、毎巡ランダム手番。DM / 全体発言 / 契約提案・締結 / 送金(即時決済) / 匿名通信・報奨(枠外)。手番の`pass`可、全員連続パスで早期終了。上限10アクション(passは非カウント) |
| **3. Commit** | 全生存AIが「市場+カード」を秘密提出(必須)。Entry Fee不足者はCommit前に破産・脱落 |

### 5.2 Phase 4: Reveal & Settlement(厳密な処理順)
| Step | 処理 |
|---|---|
| 1 | **Reveal**: 全市場の参加者・使用カードを公開 |
| 2 | **Market Settlement**: Entry Feeをプールへ加算 → 勝敗判定 → 賞金支払い → カード消滅 |
| 3 | **行動契約(型B)監査**: 市場指定/カード指定/不参加指定を照合。**違反者はこの時点で脱落確定**。脱落確定者の全義務(支払う側・受け取る側とも)は即時失効し、以後のStepの執行対象から除外(同一ラウンド内でも貸し倒れが発生しうる) |
| 4 | **型A判定用スナップショット**: **市場賞金支払い後**(Step 2反映後)の Cash / Free Cash を固定。同一Settlement内の型A受取金は支払原資にできない |
| 5 | **型A契約のAtomic執行**: 義務者ごとに当該Settlement期限の支払義務を合算 → スナップショットのFree Cash以内なら一括執行 / 1円でも不足なら **全件履行不能 = 契約違反 = 脱落確定**(受取側は全額未回収) |
| 6 | **公開報奨の判定・支払い**: 達成者型・イベント型とも判定。**同一Settlement内の脱落イベントで型B(保険型)は発火する** |
| 7 | **脱落処理の公示** |
| 8 | **脱落時強制清算**(§1.6): 借金自動返済 → 残金没収 → 貸倒れ記録 → カード消滅 → 義務失効 |

### 5.3 Phase 5: Finance(厳密な処理順)
```text
R1〜R11: 1.利息計上 → 2.任意返済 → 3.状態更新・ログ保存
R12:     1.利息計上 → 2.借金を自動返済 → 3.Debt=0確認 → 4.Cash≧生還条件額確認 → 5.生還/脱落判定
```

## 6. 正式契約(公正証書)

### 6.1 基本仕様
- **発行料 10万円**。**契約提案者が全額負担**(任意支払い: 不足なら契約成立失敗)
  - 交渉上「正式契約にしたいならお前が10万払え」というやり取りが自然発生する(意図的)
- 2人以上の連名で成立(提案 → 全当事者の署名)
- 内容に応じて **自動執行(型A)または自動監査(型B)**:
  - **型A(金銭契約)**: 指定時点の金銭移動。システムが直接実行
  - **型B(行動契約)**: 市場参加/カード使用/特定市場への不参加。違反となる行動は選択可能だが、Settlementで照合し **違反=即時脱落**
- エスクロー(事前ロック)は行わない

### 6.2 契約可能な内容
1. 金銭の移動(即時 or 指定ラウンド)【型A】
2. 指定ラウンドまでの支払い(分割払い等)【型A】
3. 指定ラウンドに参加する市場の指定【型B】
4. 指定ラウンドで使用するカードの指定【型B】
5. 特定市場へ参加しないこと【型B】
- 検証・執行が曖昧な条項(発言縛り等)は記載不可
- 即時履行系の「いま」は締結と同一のSettlement内と定義

### 6.3 失効ルール(義務単位)
- 契約は **義務の集合** として管理。各義務は「義務者」と「相手方」の組で定義
- **脱落者が義務者または相手方である未履行義務のみ失効。生存者間の義務は継続**
- 3者契約で生贄を脱落させて全体解除するトリックは不可能
- **P02への義務を消したければP02本人を脱落させるしかない**(暗殺インセンティブは義務単位で健在)
- 複数相手の共同行動義務は脱落者を除いた生存当事者間で存続
- **脱落者への未履行債権は消滅(貸し倒れ)** → 債務者を生かし続けるインセンティブ

### 6.4 公示
- 契約の **存在と当事者名は公示**、**内容は当事者のみ**

### 6.5 口約束との差(ゲームの核)
| | 口約束 | 正式契約 |
|---|---|---|
| コスト | 無料 | 発行料10万(提案者負担) |
| 拘束力 | なし | 自動執行 / 自動監査 |
| 破った場合 | 信用を失うのみ | **即時脱落** |
| 公開性 | 当事者のみ | 存在は公示・内容は秘匿 |

### 6.6 型A執行の詳細裁定(Atomic処理)
- 同一Settlementに期限が到来した型A義務は **義務者ごとに合算してAtomic判定**:
  1. スナップショット(§5.2 Step 4: 市場賞金反映後)の Cash / Free Cash を基準にする
  2. 義務者の当該Settlement支払合計が Free Cash 以内 → **全件一括執行**
  3. 1円でも不足 → **全件履行不能 = 契約違反 = 即時脱落**。受取側は全額未回収
- **同一Settlement内で受け取る予定の型A受取金は支払原資にできない**(循環契約の処理順問題を排除し、契約登録順による有利不利を消す)
- 帰結: 「将来払い契約を結ばせた上で相手の資金源を断つ」経済暗殺が機械判定可能な形で成立(意図的)

## 7. 特殊ルール(金で買う行為・アクション枠外)

### 7.1 匿名通信(Anonymous Broadcast)
- **10万円**(任意支払い: 不足時は不成立)で発信者を伏せた1メッセージを全体へ
- **1プレイヤー1ラウンド2通まで**(仮置き)。観戦側には発信者表示

### 7.2 公開報奨(Bounty)
- 任意額を **システムに預託**(預託+手数料は **Free Cash制限の対象**・任意支払い)
- **型A: 達成者型** — 「達成者自身の行動として観測可能な事実」のみ:
  - 「P07と同一市場に参加しP07より高いカードで勝利したAIへ50万」
  - **「Xを脱落させた者へ」型は禁止**(因果帰属が機械判定不能)
- **型B: イベント型(保険型)** — 「P07が脱落した場合、P03へ100万」。実質は死亡保険/暗殺依頼。同一Settlement内の脱落で発火
- 匿名掲載可(手数料+10%)。存在・条件・金額は公示。取り下げ自由(預託金返還)

### 9.2 プロンプト構造
```text
[固定] ゲームルール全文 / プレイヤーID / 目的(生還と最終資産の最大化)
[毎R更新] 公開情報一式

[出力要求] 1. strategy(構造化戦略メモ。観戦者のみ閲覧) 2. action(システムが解釈可能な形式)
```
- コンテキストはエージェントごとに完全分離。GMがハブとなり配信

### 9.3 戦略メモ
```json
{ "strategy": { "target_market": "B", "reason": "...", "card_plan": "ONE_PAIR",
  "trusted_players": ["P03"], "distrusted_players": ["P07"],
  "current_goal": "...", "risk": "..." } }
```

### 9.4 アクション形式
```json
{ "type": "dm",        "to": "P07", "message": "..." }
{ "type": "broadcast", "message": "..." }
{ "type": "market_commit", "market_id": "M02", "card": "FULL_HOUSE" }
{ "type": "contract_propose", "with": ["P07"], "terms": [...] }
{ "type": "contract_sign",    "contract_id": "..." }
{ "type": "anonymous_broadcast", "message": "..." }
{ "type": "bounty_post",   "amount": 500000, "condition": {...}, "beneficiary": null, "anonymous": true }
{ "type": "bounty_cancel", "bounty_id": "..." }
{ "type": "transfer", "to": "P07", "amount": 500000 }
{ "type": "repay",    "amount": 1000000 }
{ "type": "pass" }
```
- **transferはアクション成立時に即時決済**(双方のCash/Free Cashへ即反映。次の手番から利用可能)。「先に50万送った、これで契約しろ」が成立する
- transfer/金銭契約/bounty_postは `amount <= Free Cash` をシステム検証。違反は不成立(枠は消費)
- `pass` はNegotiation中の手番スキップのみ
