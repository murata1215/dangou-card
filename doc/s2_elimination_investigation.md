# S2シミュレーション 脱落条件・乱数シード同期 調査レポート

- 調査日時: 2026-08-13 13:00 JST
- 対象: S2 Botシミュレーション 1,000試合の結果異常値の検証
- 方針: コード変更なし、調査と報告のみ

---

## 調査の動機

S2 Botシミュレーション（1,000試合）で以下の結果が出た:

1. R1-R11の脱落者が S1/S2 ともに**全てゼロ**
2. R12到達人数が全1,000試合で**8人**
3. R01の総資産が S2/S1 = **0.93x**（S2の方が低い）

これらが仕様通りなのか計測上の問題なのかを確定させる。

---

## 1. 脱落条件の仕様確認

### 判定: **仕様通り**

### 脱落ルート一覧

仕様書（v0.5 &sect;1.1-1.2, &sect;5.2-5.3）とエンジン実装の両方を確認した。
脱落ルートは3つあり、仕様と実装は**完全に一致**している。

| # | ルート | 条件 | 判定タイミング | 実装箇所 |
|---|--------|------|--------------|---------|
| A | **破産** | Cash < Entry Fee (10万円) | **毎ラウンド** Commit フェイズ | `game.py` L429-441 |
| B | **契約違反** | 型B行動契約違反 or 型A金銭契約履行不能 | **毎ラウンド** Settlement Step 3, 5 | `settlement.py` L140-219 |
| C | **条件未達** | Debt > 0 or Cash < survival_cash | **R12 Finance のみ** | `finance.py` L102-140 |

### 生還判定はR12のみ

`finance.py` L62:
```python
if round_num < config.num_rounds:
    # R1-11: 利息計上 + 任意返済のみ。生還判定なし
else:
    # R12: 自動返済 → 生還判定
```

**R1-R11では「資産が少ない」だけでは脱落しない。**
脱落するにはルートA（破産）またはルートB（契約違反）が必要。

### Botシミュレーションで途中脱落がゼロの理由

1. **ルートA（破産）が発動しない**: 全Botの初期借入額は120万-700万円。
   Entry Fee は10万円/ラウンド。12ラウンドで計120万円。
   最も少ないConservative Bot（120万借入）でも、
   市場賞金を1回でも獲得すればEntry Feeを払い続けられる。
   実際にはR1で全員が何らかの賞金を獲得するため、破産は起きない。

2. **ルートB（契約違反）が発動しない**: Bot 8種は**契約を一切使用しない**。
   - Collusion Bot: `propose_collusion` をbroadcastするが、正式契約（ContractProposeAction）は出さない
   - Betrayal Bot: `accept` をbroadcastするが、ContractSignAction は出さない
   - その他6種: Negotiation中は返済（RepayAction）かパス（PassAction）のみ
   - 結果: 契約が存在しないため、違反も発生しない

3. **ルートC（条件未達）はR12のみ**: 仕様通り。

**結論**: R1-R11脱落ゼロ・R12到達全員8人は**仕様通りの期待動作**。

### LLMトライアルとの比較

LLMトライアルでは途中脱落が発生している:

| トライアル | ラウンド | プレイヤー | 理由 |
|-----------|---------|----------|------|
| trial_B (game01) | R1 | P02 | bankruptcy |
| trial_B (game01) | R3 | P01 | bankruptcy |
| trial_B (game02) | R5 | P01 | bankruptcy |
| trial_C (game01) | R12 | P01 | bankruptcy |

LLMはBotと異なり:
- 高額借入（最大1000万）を選択するケースがある
- Entry Fee支払い後に資産がゼロに近づく
- 市場で負けて賞金を得られないと次ラウンドのEntry Feeが払えなくなる

→ **途中脱落はLLM対戦特有の現象であり、Botシミュレーションでは構造的に発生しない。**

## 2. 資産が減少する局面の洗い出し

### 判定: **仕様通り**

ゲーム中にプレイヤーの `cash` が減少する経路を全て列挙した。

| # | 経路 | フェイズ | 金額 | 必須? | Botが使用? |
|---|------|---------|------|------|-----------|
| 1 | Entry Fee 支払い | Commit | 10万円/R | YES | YES (全Bot) |
| 2 | 契約発行料 | Negotiation | 10万円/件 | NO | NO (Botは契約を出さない) |
| 3 | 匿名通信料 | Negotiation | 10万円/通 | NO | NO (Botは使わない) |
| 4 | 賞金首預託 | Negotiation | 可変 | NO | NO (Botは使わない) |
| 5 | 即時送金 (Transfer) | Negotiation | 可変 | NO | NO (Botは使わない) |
| 6 | 債務返済 | Negotiation | 可変 | NO | YES (全Bot, _try_repay) |
| 7 | 倍掛け預託 (S2) | Settlement後 | 可変 | NO | YES (6種Botが条件付き) |
| 8 | R12自動返済 | Finance | min(cash, debt) | YES(R12) | YES |
| 9 | 強制清算 | 脱落時 | 残金全額 | YES(脱落時) | YES (R12のみ) |

### 利息について

利息 (1.5%/R 複利) は **`debt_balance` を増加** させるが、`cash` は直接減少しない。
ただし、R12の自動返済時に `min(cash, debt_balance)` が差し引かれるため、
利息の蓄積はR12の生還判定に間接的に影響する。

### Botシミュレーション中の実動作

- **Entry Fee**: 8人 x 12R = 96回/試合（全試合で発動）
- **債務返済**: 全BotがNegotiationフェイズで `_try_repay()` を実行
  - 残りラウンド数 x Entry Fee + 予備(20万) を手元に残し、超過分を返済
- **倍掛け預託 (S2)**: 1,000試合で計17,379回選択（Bot 6種の戦略による）
- **契約・匿名通信・賞金首・送金**: **全て0回**（Botが使用しない）

## 3. 乱数シード同期の検証

### 判定: **同期している。0.93xの原因は倍掛け預託の未計上**

### 検証方法

同一シード(42)でS1/S2の1試合を実行し、各ラウンドのコミット内容を比較した。

### 検証結果

**R1コミット（S1 vs S2）: 完全一致**

```
S1 R1: [('P01','M03','FULL_HOUSE_1'), ('P02','M02','HIGH_CARD_1'), ...]
S2 R1: [('P01','M03','FULL_HOUSE_1'), ('P02','M02','HIGH_CARD_1'), ...]
→ 完全一致
```

**R2コミット（S1 vs S2）: 完全一致**

```
S1 R2: [('P01','M01','FOUR_OF_A_KIND_1'), ('P02','M03','HIGH_CARD_2'), ...]
S2 R2: [('P01','M01','FOUR_OF_A_KIND_1'), ('P02','M03','HIGH_CARD_2'), ...]
→ 完全一致
```

### R01 総資産の差分の原因

| 指標 | S1 | S2 | 差分 |
|------|-----|-----|------|
| R1後 total_cash | 10,780,000 | 10,320,000 | -460,000 |
| 倍掛け預託額 | 0 | 460,000 | +460,000 |
| **cash + deposits** | **10,780,000** | **10,780,000** | **0** |

**原因**: スナップショットの `total_assets` は `p.cash` のみを計上しており、
倍掛け預託としてシステムに預けられた資産を含んでいない。

S2では R1 Settlement 後に `_process_double_up()` が呼ばれ、
市場勝者のうち倍掛けを選択したBotの賞金が預託として回収される。
この回収分がスナップショットの `total_assets` に反映されないため、
S2の R01 総資産が S1 比 0.93x と計測された。

**これはバグではなく、集計方法の特性。**
レポートの「総資産」は「手持ち現金」を意味しており、
「預託中の倍掛け資産」は含まれていない。
比較レポートに注釈を追加すべきである。

### RNGずれの有無

- `GameRng` は `_master` → 3サブRNG (`_negotiation_rng`, `_market_rng`, `_general_rng`) に分岐
- Bot RNG (`self.rng`) は `game_seed * 100 + player_index` で個別初期化
- `choose_double_up()` はBot RNG を消費するが（RandomBotの `self.rng.random()` 等）、
  GameRng は消費しない
- S2の `_process_double_up()` は `_build_visible_state()` を呼ぶが、
  これはRNGを消費しない（dict構築のみ）
- **結果: R1, R2のコミットがS1/S2で完全一致しており、RNGは同期している**

ただし、倍掛けを選択すると賞金が回収されるため、
以降のラウンドでBotの `cash` が変わり、返済行動 (`_try_repay()`) の判断が変わる可能性がある。
これによりR3以降で行動が分岐する可能性はある。
しかしこれはRNGの「ずれ」ではなく、「ゲーム状態の正当な分岐」である。

## 4. 生存者数が減った局面のデータ有無

### 判定: **Bot simulationでは存在しない。LLM対戦では存在する。**

### Bot simulation

- S2比較レポートの「生存者数別 高騰発生率」テーブル: **alive_count=8 の行のみ**
- S1/S2 各1,000試合: 全試合で R12到達人数 = 8人
- 既存のS1シミュレーション（8,400試合, `logs/sim_20260809_170843/`）: 同様に全R12脱落

→ Bot simulationでは構造的に途中脱落が発生しないため、
  生存者数が7人以下のデータは存在しない。
  **「生存者数別 高騰発生率」の表が8人の行しかないのは正常。**

### LLM対戦

- trial_B: R1, R3 で破産（2名脱落 → 生存者6名の状態が発生）
- trial_C: R12のみ破産（途中は全員生存）

→ LLM対戦では途中脱落が発生するため、生存者数が減った局面のデータは存在する。

### 高騰閾値の検証への影響

S2仕様書 &sect;8.3 の懸念:
> 4-6人時、高騰閾値(1/2)で常時化しないか

Bot simulationでは常に8人生存のため、この懸念を検証できない。
**LLM対戦データ（20人版）での検証、
または途中脱落を人為的に発生させるBot（高額借入+無戦略Bot）の追加が必要。**

## 総合判定

| 調査項目 | 判定 | 備考 |
|---------|------|------|
| 1. 脱落条件の仕様確認 | **仕様通り** | R1-R11脱落ゼロは期待動作。生還判定はR12のみ |
| 2. 資産減少局面 | **仕様通り** | Botが使う減少経路はEntry Fee・返済・倍掛け預託のみ |
| 3. 乱数シード同期 | **同期している** | 0.93xは倍掛け預託の未計上が原因。RNGずれなし |
| 4. 生存者数データ | **Bot simでは8人固定** | 途中脱落がないため。LLM対戦にはデータあり |

### 推奨アクション（コード変更は本調査では行わない）

1. **S2比較レポートに注釈追加**: 「総資産」は手持ち現金のみで、倍掛け預託を含まない旨を明記
2. **スナップショットに `total_deposits` フィールド追加**: 預託中資産を別途記録し、レポートで `cash + deposits` を表示する選択肢を提供
3. **高騰閾値の検証**: 途中脱落が発生する条件でのシミュレーション（高額借入Bot追加、またはLLM対戦データ使用）を検討
4. **仕様と実装の不一致**: **なし**。全調査項目で仕様と実装が一致
