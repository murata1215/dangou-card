# API課金実績台帳

走行（LLM実戦試験・本走）ごとに1セクションずつ追記していく台帳。
「プロバイダ管理画面の実課金」と「ログ集計値（`cost_usd` 合計）」を突き合わせ、
単価テーブル（`llm/models.py`）の精度を継続的に検証する目的で作成する。

## 運用ルール

1. **実課金の記録方法**: 走行の前後にプロバイダ管理画面のスクリーンショットから
   人間が手動で値を読み取り、「実課金」として本台帳に記す。自動取得は行わない。
2. **集計窓が社ごとに異なる点に注意する**: 各社の画面表示は次のように集計単位・期間が
   異なるため、**必ず「同じ画面の同じ項目」を走行前後で比較し、その差分を取ること**。
   異なる項目・異なる期間の値を比較しない。
   - Anthropic = APIキー単位の累計（Cost）
   - OpenAI = プロジェクトの月次 Monthly spend
   - Google = プロジェクトの月次上限に対する使用量（Project月次上限表示）
   - Moonshot = アカウントの Total Consumption（累計）
   - xAI = チーム単位の直近30日 Credits usage
   - DeepSeek = アカウント単位の直近30日 Total cost
3. **ログ集計値の定義**: `logs/llm/<run_id>/llm_logs/game01_P*_llm_calls.jsonl` の
   各行に記録された `cost_usd` を、当該走行・当該プレイヤーについて合計した値。
4. **乖離判定**: 実課金とログ集計値の乖離が **10%を超えた社は単価テーブル
   （`llm/models.py` の `input_price_usd_per_million` / `output_price_usd_per_million` /
   `cached_input_price_usd_per_million`）の検証対象**とする。
5. **通貨換算はすべて概算**である。Google（¥建て）を$換算する場合や、逆に$を¥で
   参考表示する場合は、記録時点のレートによる概算であり、会計上の厳密な値ではない
   ことを明記する。
6. 数値は走行直後に記録した値をそのまま台帳に転記する。後日の再計算・推測による
   補完・丸め直しは行わない（社別集計と席別集計の単純和がわずかに一致しない場合も、
   両方の値をそのまま残し、丸めによる差である旨を注記するに留める）。
