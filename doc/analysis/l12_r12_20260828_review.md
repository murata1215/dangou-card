135席ラウンド中 **61件（45.2%）が Free Cash = 0**。R1は12人中9人（75%）が0（>0はP06/P08/P10のみ）。
全席が初手で120万〜1,000万円を借入しており、`free_cash = max(0, cash - debt_balance)`

送金・報奨・（現金付き）カードトレードが構造的に封じられる。transfer・bounty_postが選択可能だった
631/1,375ターンのうち、さらに744ターン（54.1%）はFree Cash=0で機械的に不可能だった。

facts.md記録済みの拒否理由4件は全て「FULL_HOUSE→ONE_PAIRへのdowngradeは不利」という同旨:

- P07: 「P03のトレードはONE_PAIR⇄FULL_HOUSEで明らかに不利、拒否」
- P11: 「P03のトレードはFULL_HOUSEをONE_PAIRにdowngradeする不利トレードなので即拒否」
- P12: 「P03からのトレード提案（FULL_HOUSEとONE_PAIRの交換）は手札価値を大幅に下げるため拒否する」

→ プロンプトの表示内容は客観的に見ても提案者側に一方的に有利な条件であり、4件の拒否は**合理的判断**
だったことがプロンプト文面から裏付けられる（プロンプト情報の欠落や誤解が原因ではない）。

**P03のカードトレードへの言及推移**（全ゲームで3回のみ）:
R3 turn1（提案）→ R3 turn9（DM中で当該トレードに再言及）→ R4 turn1「まずは情報収集とカードトレード
交渉から始める」（意図表明のみ）→ **R4 turn2〜R12脱落までの残り全ターン、カードトレードへの言及は
0件**。1回の拒否と1回の再挑戦意図の表明のみで、以降は完全に選択肢から外れている。

**カードトレード言及の全18件**（席・ラウンド・種別）:

```
P02 R3t4, P02 R8t6, P02 R12t1, P02 R12t6
P03 R3t1(propose), P03 R3t9, P03 R4t1, P03 R4t2

```

**LLMの誤認識（新規発見）**: Free Cashとカードトレード可否を混同する誤った推論が2件確認された。
`card_trade_propose`の可用性はラウンド番号のみで判定され（`llm/prompt_builder.py:667-766`）、
現金0円のカード⇄カード純粋交換にはFree Cashは不要だが、以下2件はこれを誤解していた:

- P05 R6t9: 「現在のFree Cashは0で追加の現金移動やカードトレードができないため」（事実誤認）
- P12 R4t4: 「Free Cashが0のためカードトレードや送金は使えない」（事実誤認）

→ カードトレードの機能不全は、(1) R3の唯一の提案が客観的に不利な条件だったための正当な拒否、
(2) 提案側P03がR4以降完全に関心を失った（原因は判別不能。手札構成の変化、他の交渉手段への
シフト等が候補だが reasoning に明示的理由なし）、(3) 少なくとも2件でFree Cashに関する誤認識が
利用回避の一因になった、の複合。**主因は(d)LLM能力限界**（不利トレード後の学習が「二度と使わない」
という極端な形で固定化し、対案提示や条件変更を試みる思考に至らなかったこと、および誤認識の存在）。

### C-2. 未署名2件の一方的義務性

**C_f41da629**（P02→P07、R3提案）: 義務はP02→M02参加+THREE_OF_A_KIND使用、P07→M02参加+

500,000円支払い（型A）。P02の拒否理由「THREE_OF_A_KINDは私の手札にありません。署名すれば即違反
脱落です」（facts.md 3-3引用）は、**P02が実際に保有していないカードランクの使用を義務付ける
内容**だったことを示す。これは対称的な取引条件に見えて、実際にはP02にとって履行不可能な罠
（署名した瞬間に型B違反が確定する契約）であり、**客観的に一方的（相手に不利）な提案**だったと
判定できる。P02はこれを見抜いて拒否しており、`contract_sign`前に相手の手札を検証する仕組みは
システムには存在しない（情報の非対称性はゲーム設計上の意図と解釈できるため、これ自体を不具合とは
評価しない）が、見抜けなかった場合のリスクは実在する（Part G参照）。

### C-3. 「契約違反脱落0件」の意味

母数は成立4件・義務7項目のみであり、**0件という結果は「契約が慎重に運用された証拠」と
「単に契約自体がほとんど使われなかったことの帰結」の両方から説明可能**で、この4件だけでは
判別不能。ただし、facts.md参照先の前走`trial_C_l12_r12_20260827`の中断調査記録
（`doc/devlog/2026-08-28_051043.md`、INDEXの当該行より）には「P02が史上初のcontract_violation
脱落を確認」との記載があり、**契約違反による脱落自体はこのシステムで発生し得る事象**であることが
別走行で示されている。したがって本走行の「0件」は「ルールが機能した結果」というより、

### E-9. 倍掛け単独市場除外（`from_solo_market`）の論理的到達不能性

`engine/game.py:1120-1230`を直接読み込み、以下を確認した:
- `:1124` 単独市場判定`len(mr.participants) == 1`は仕様通り正しい
- `:1152` 成功分岐への進入条件は`non_solo_winners[pid] > 0`（非単独市場での勝利が1件以上）で、
  この条件自体が単独市場除外を**正しく機能させている**（ルールのゲーティングは妥当）
- ただし`:1156-1161`の`all_solo`判定と`from_solo_market`記録は**成功分岐の内側**にのみ存在する。

ではなく、**この指標が構造上観測不可能であること**を意味する（原因区分**(a)システム不具合**、

forfeit（P03 R9: M01単独参加で740,000円獲得も他市場で非勝利、P11 R12: M03単独参加で2,020,000円
獲得も他市場で非勝利）の2件はforfeit分岐に理由フィールドがないためログからは確証できず、
**判別不能**として扱う。
