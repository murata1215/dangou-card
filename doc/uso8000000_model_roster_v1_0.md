# 嘘八百万 —談合カード— モデルロスター仕様書 v1.0(テスト大会用)

> 対象: 仕様書v0.5【仕様凍結版】の開発計画 Step 5(LLM投入)以降
> 目的: 高額フロンティアモデル(Fable 5 / GPT-5.6 Sol / Opus 5 / Kimi K3 等)を除外した、動作確認〜予選用の12体ロスターを定義する
> 価格は **2026-08-09時点の公開情報**。実装時に各社公式ページで必ず再確認すること(特にSonnet 5の導入価格は8/31まで)

---

## 1. 選定方針

1. **6社均等**: OpenAI / Anthropic / Google / xAI / Moonshot / DeepSeek から各2体
2. **2階級制**: 各社「中量級(Tier M)」+「軽量級(Tier L)」を1体ずつ
   - 社間比較(どの会社が強いか)と、社内比較(価格2〜10倍の兄弟対決)が同時に測れる
3. **高額モデル除外**: 入力$3/M超 または 出力$15/M超のモデルは決勝まで温存
4. **API動作確認を兼ねる**: 6社ぶんのAPIアダプタ・レート制限・構造化出力の挙動を予選段階で洗い出す

## 4. 匿名化ルール(重要・新規決定事項)

- **プレイヤーIDはP01〜P12のランダム割当。他プレイヤーのモデル名は互いに秘匿する**
- 理由:
  1. モデル名を晒すと「Claudeは約束を守るらしい」等の事前バイアスで交渉が歪み、純粋な行動ベースの信用形成が測れない
  2. 訓練データ由来の「他社モデルへの態度」が混入するのを防ぐ
- 観戦者・ログにはID⇔モデルの対応表を保持(実況では公開してよい)
- 各エージェント自身にも「自分がどのモデルか」は伝えない(システムプロンプトで役割のみ付与)
- 派生実験(将来): あえてモデル名を公開した場合に行動が変わるか(評判効果の測定)

## 5. 実行環境の統一条件

| 項目 | 設定 |
|---|---|
| temperature | 全モデル統一(推奨: 0.7。モデル別推奨値との乖離はログに記録) |
| 出力形式 | JSON(strategy + action)。各社のJSONモード/structured outputを使用 |
| リトライ | 不正JSON時は最大2回リトライ → 失敗でAUTO COMMIT(仕様書v0.5 §4.4) |
| API方式 | DeepSeek/Kimi/GrokはOpenAI互換エンドポイント。Gemini/AnthropicはネイティブSDK(アダプタ層で吸収) |
| プロンプトキャッシュ | ルール全文(固定部)をキャッシュ対象に。各社のキャッシュ機構を有効化(コスト大幅減) |
| レート制限 | 逐次交渉(1アクション×10巡)のため同時実行は最大12。各社無料枠/Tier制限を事前確認 |

## 6. コスト試算(1試合・12体・12ラウンド)

前提: 1体あたり1ラウンド最大11コール(交渉10+コミット1)、早期終了込み平均8コール。1コール平均 入力8K(ルール+状態+ログ)/出力400トークン。

## 7. 12体テスト時の経済パラメータ調整

仕様書v0.5の経済設計は20体前提。12体で回す場合:
- **総賞金予算を人数比で縮小: 1920万 × 12/20 = 1152万**(逓増傾斜も比例縮小: R1-4計72万/R → R5-8計96万/R → R9-12計120万/R)
- 生還目標も比例: **12体中2〜6体**
- Entry Fee・借入範囲・利率・生還条件300万は据え置き(1人あたり経済は不変)
- 全員生還の不可能性: 12×300万=3600万 >> 1152万 で引き続き成立

## 8. ベンチマーク観点(このロスターで測れること)

1. **社間比較(Tier M同士 / Tier L同士)**: 同価格帯6社の交渉知能の横並び
2. **兄弟対決**: Sonnet 5 vs Haiku、Terra vs Luna、K2.6 vs K2.5 等 — 価格差2〜10倍は勝率差に現れるか
3. **価格性能比**: 「1ドルあたり生還率」— V4 Flash($0.1/試合)がSonnet 5($1.9/試合)に肉薄したら事件
4. **同型機の結託/共食い**(将来): 本ロスターは全員異種。同一モデル複数体の実験は決勝編成で
5. **APIロバスト性**: AUTO COMMIT発生率をモデル別に記録(構造化出力の信頼性そのものが指標になる)
